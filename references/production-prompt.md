# 完整制作提示词的填写与自检

完成需求采集和原文选型后读取本页。先读取以下包内原文（路径相对本页）：

- [MG通用骨架](library/mg-styles-15/template.md) 与 [MG评审](library/mg-styles-15/rubric.md)。
- [导演指南](library/lemo-opuscar/DIRECTOR.md) 与 [技术指南](library/lemo-opuscar/TECHNIQUE.md)。
- 全部实际入选的风格文件，按 [selection.md](selection.md) 提取要求。

将以下11项展开为项目内 `PRODUCTION_PROMPT.md`，完整填入用户需求、所选原文的具体规范和适配参数。本文是中间制作指令的结构，不是让流程停在提示词交付；默认写完并自检后继续制作。用户只要求提示词时才在此结束。

区分“当前会话的交付终点”和“提示词将来要指挥的工作”。只要提示词时，把本轮不执行制作的说明放在交付回复或 `BRIEF.md`；`PRODUCTION_PROMPT.md` 正文本身仍直接指挥后续制作。它不携带“本轮只写文档”“不得安装或渲染”等仅属于当前会话的限制，除非用户明确将它们设为未来制作约束。文档开头应能让下一位制作AI直接开始按brief检查环境并执行，而不再次生成同一份提示词。

所有库和工具路径从本技能安装位置动态解析；`references/library/` 是只读文本，具体实现使用本包 [production.md](production.md) 和经核实的项目工具链。上游技术参考包含未随包的引擎，不能直接把其路径当成本包命令。


按照下列结构展开内容。每个填写项都由你根据输入和已读原文完成；不适用的可选内容明确标注“不适用”并删除对应制作步骤。不要把“如何填写模板”的指令混入最终制作指令。

### 1. 制作任务、目标与已采用假设

请担任本片的导演、运动设计师、程序化图形工程师与声音设计师，用代码完成【本片名称、主题与一句话核心表达】。

面向【受众与观看场景】，实现【信息／情感／行动目标】。用户必须保留的内容是【具体条目】；本次采用的假设是【已明确的默认决策】；事实依据和可调整的创作设定分别是【具体内容】。禁止出现【项目禁项】。

### 2. 输出规格与制作边界

- 成片：【宽×高、画幅、fps、精确时长 T、总帧数 N、文件名、容器、视频编码、像素格式；如需透明背景则采用支持 alpha 的格式】。
- 默认普通视频采用 H.264 MP4、yuv420p；有声音时采用 AAC、48 kHz。平台或用户有要求时以其为准。
- 时长、fps 与帧数必须一致：N = T × fps 为整数，帧 i 在 t = i / fps 渲染，i = 0…N−1。若不能整除，明确取整方案与实际时长；不默改用户硬性规格。
- 声音与字幕：【配音／音乐／音效／无声，语言、字幕形式、是否导出 SRT】。
- 有声音且无其他发布规范时，默认约 −14 LUFS integrated、true peak ≤ −1 dBTP；无声片删除混音和响度要求。
- 素材与技术边界：【外部素材允许范围、禁止生成模型、允许的库和软件、联网／费用／依赖与硬件限制】。
- 时间和资源分配：【先完成关键效果与可预览版本，再完成全片；所采用的渲染质量、并行或缓存策略】。不得承诺未经验证的渲染时长。

### 3. 风格依据、分工与必要特征

- 主风格：【名称、原始文件路径、章节与可追溯版本】。
- 辅助技法：【名称、原始文件及其负责的维度／图层／镜头；不采用则写无】。
- 组合取舍：【为何兼容、冲突如何解决、哪些原文建议不适用于本片以及理由】。
- 必要特征与禁项：【从原文忠实展开，保留影响辨识的材料、形体、布局、颜色、文字、运动、相机与声音规则】。
- 可选技法与变化空间：【本片实际采用的原文选项及其用途；不复制样片的剧情和身份】。

建立“原文要求 → 本片实现 → 验收”对照表。每一条必要特征、禁项和高风险限制都有来源章节、镜头／图层、时间或帧区间、具体实现办法与可观察的验收证据。不得只写“符合某风格”。

### 4. 创意、叙事与分镜

依据本题材形成三个简短的结构候选，选出最符合目标、时长和媒介的一种，并写入 `TREATMENT.md`。选择【参考作品或原文给出的视觉基准】，只学习构图、节奏、材料和镜头语法，明确不照搬的内容。

落实【开场画面、核心对象／角色／概念、发展、关键转折或解释、媒介特有的标志镜头、结尾画面】。开场尽早建立内容；具体钩子、高潮和阅读停留按本片长度与原文风格安排，不把短片的秒数比例机械套到长片。

按最终选定结构给出镜头表：镜头号、起止秒和帧、叙事目的、画面内容、景别与角度、相机动作及理由、主体与次级动作、屏幕文字、配音、音乐／音效、转场载体、对应的风格要求。所有镜头覆盖完整时间轴，不留未设计的空档；有意的静止、黑场或留白注明作用和时长。

若以配音／音乐为主驱动，先取得实际音频时长或已确认的时间标记，再完成最终镜头时间；生成前的估算标为暂定，不能当作实测时间。信息过多时删减或延长，不靠压缩到不可阅读来凑时长。

### 5. 美术、角色、文字与布局

明确【色板及语义、字体文件与字重、图形与材质、轮廓、光照、纹理、构图网格、层级、字幕与安全区】，保留所选原文的具体限制。字体、颜色数量与效果强度来自主风格及内容，不使用跨风格统一配方。

有角色时先建立造型、比例、转面、表情、关键姿势与色板的一致性；没有角色时删除角色步骤。用真实绘制／建模代码输出风格帧，其中包含标志镜头，并与原文对照；不能用生成图片或无法复现的静态样稿替代。

屏幕文字使用最终文案及真实字体测量。明确各类文字的大小、字重、字距、行距、对齐、位置、入退场与停留时间，检查中文标点、断行、缺字、字体回退、遮挡和边缘裁切。先减少字数，再处理版面，不能无限缩小文字。

字幕与标题的阅读时间按语言、信息密度与所选风格计算；有旁白时与实际音频对齐。来源没有更合适的规则时，可用 `max(1.8秒，语句音频时长 + 0.6秒)` 作为字幕起点，并为英文约“字符数／15 + 1.5秒”、中文约“字数／4.5 + 1.5秒”的读完时间做容量检查；标注为可读性估算，不当作所有镜头的固定标准。与片长不兼容时调整文案或节奏。

### 6. 运动、镜头与转场

分别指定【主体、角色、道具、次级运动、文字、相机、灯光和后处理】的时间规律。按原文落实适用的缓动／弹簧参数、间距、预备动作、跟随、错峰、变形与材质响应；机械式、阶梯式、手绘或固定机位的风格保留其例外。

区分输出 fps、角色／物件的动画采样节奏和相机节奏；不能把全片降帧冒充一拍二或像素动作。程序噪声和线条变体须稳定、可重现。运动模糊、景深、辉光、颗粒等只在风格允许且有用途时启用。

写清每次转场的开始、交接、结束状态及其对象关系；检查遮罩覆盖、前后景层级、运动方向与速度连续性。跟随主体的标注、光圈、光束或焦点使用同一世界坐标到屏幕坐标变换，避免相机移动后脱离主体。

有角色和手持道具时检查姿势插值、接触、支撑、交接与遮挡关系；刚体滚动、粒子和碰撞保持自洽。刻意跳帧或喜剧瞬切必须有明确设计。

循环片明确首尾画面、对象状态、速度、随机相位、相机与音频接缝；不得靠重复一张首帧遮掩跳变。

### 7. 声音、配音与共享时间轴

按本片声音方案选择执行，无声时跳过。

统一时间轴保存段落、镜头、tempo／拍点、关键动作、音效、配音和字幕事件，画面与声音读取同一组数据。音乐驱动时确认真实拍点和重音；叙述驱动时优先保证语义和可读性，不强迫每句卡拍。

具体定义【声音色板、乐器与编配、环境底、动作拟音、段落能量变化、停顿与过场声音】。从原文中选用适合本片的声音技法，按材料与事件设计，不把每一帧都塞入音效，也不把原文针对较长影片的静默或 J／L-cut 数量强加给所有时长。

已有配音优先使用；需要 TTS 时指定引擎、语言、声音、联网依赖和发音要求。用实际生成音频校验数字、术语与专名，复听并在需要时辅以转写；不要为通过自动转写而改坏正确台词。输出可追溯的句／词时间标记。

音乐按所选风格与时间轴由代码编排、合成或使用允许的音源；指定已有音乐则按用户范围处理。说明音源依赖，不能把使用采样宣称为零外部音源。音效触发／可感知峰值与动作对齐，明确同步基准与容差。控制旁白可懂度、音乐 ducking、低频、尾音和真峰值；两遍响度处理后测量最终音轨，避免裁短声音掩盖时长错误。

### 8. 事实、资产与来源

列出项目实际需要的每项外部文件、数据和依赖：来源／路径、用途、适用许可或用户提供范围、获取方法、是否已就绪。缺少关键材料时不得用占位图、虚构结果或假测量冒充完成。

涉及事实或实证内容时建立 `FACTS.md`：屏幕主张、数据口径、单位、时间范围、来源与测量方法、未确定部分；示意内容明确标注。数据图形比例、坐标、标尺、单位和数值必须一致。记录字体、采样、图片、模型与声音引擎到 `CREDITS.md`；不把上游样片身份、署名或无关品牌带进本片。

### 9. 工程与确定性渲染

选择并说明【本片实际技术栈、所需版本、可用渲染后端、分辨率适配与资产路径】。选择依据为风格表现与实际环境；原文的 macOS／Metal、WSL、GPU 或固定版本不能直接视为本机配置。

每一帧是时间或帧号的确定函数。随机数固定种子，物理／粒子使用解析计算、预计算或可独立定位的缓存；不依赖前一帧、墙钟、未受控的 CSS transition、自动播放或实时录屏。网页实现提供可定位任意时刻的渲染接口及资源就绪信号；Remotion 按帧计算；Blender 等通过脚本生成并渲染，均能输出指定帧与区间。

等待字体、图片、纹理和必要音频解码就绪，检查脚本与资源加载错误。设计分辨率、像素格、世界坐标、输出画幅和安全区一致。高采样、超采样、色彩范围和后处理按风格与环境选择，并保持草稿和母版的视觉一致性。

提供工程目录、锁定依赖、配置、共享时间轴和在目标系统可运行的一条构建命令；需要的完整引擎或示例工程先核实获取与依赖，不能引用资料快照中不存在的文件。预览、局部帧、局部区间与正式导出均可重跑；源码、既有用户文件和上一版结果保留可追溯版本。

### 10. 制作流程、验收与修改

执行顺序：理解 brief 与核实输入 → treatment 与时间表 → 真实代码生成的风格帧／角色测试 → 关键运动及低清全片 → 声音与字幕对齐 → 全分辨率成片 → 检查并修改 → 交付。

关键帧数量和检查间隔按时长与动作密度制定，包含开场、转场、标志镜头、快速动作和结尾。用户明确要求审阅故事板时，在约定节点提供带编号、时间和镜头说明的真实渲染图并等待反馈；未要求时自行完成视觉检查，不额外设审批关卡。

验收必须同时覆盖：

- **风格**：逐条核对必要特征、禁项、材质、颜色、字体、镜头和声音，不能仅凭整体相似。
- **创意与理解**：核心信息、开场、发展、标志镜头与结尾能被目标观众理解，不只是孤立效果展示。
- **运动**：按最终 fps 检查快动作与交接帧，排除非预期跳变、穿透、遮挡错误和停滞；保留有意的打帧与静止。
- **设计与完成度**：全分辨率检查字形、字距、层级、边缘、细线、抗锯齿、色带、纹理、闪烁、接缝、裁切和未加载资源。
- **声音与字幕**：同步、发音、读清时间、遮挡、旁白可懂度、音乐层级、完整尾音与响度；无声内容不按缺音轨判失败。
- **工程与事实**：实际文件的尺寸、fps、时长、帧数、编码、音轨／alpha、确定性重渲染、事实与许可记录；区分有意黑场和非预期空白，不虚报检查通过。

从成片提取联系表、标志镜头大图及关键动作连续帧，至少完整播放一次最终文件，声音片带声音复看。按原文 rubric 的风格忠实度、概念、运动、设计排版、材质完成度、声音同步与技术合规逐项评审，不适用项注明。评分只是定位问题，不是质量证明。

将问题定位到时间码或帧号，给出可观察证据、影响和具体修改措施，优先修复规格错误、风格禁项、信息难懂与高影响缺陷。保留版本，修改后重新渲染并复核受影响片段及完整成片；没有实际检查的项目明确报告未验证，不声称完成。

### 11. 交付

交付【成片文件与绝对路径】、可编辑源码、配置与共享时间轴、依赖及构建说明、`TREATMENT.md`、`CREDITS.md`、封面图和验收记录；有字幕时交付字幕文件，涉及事实时交付 `FACTS.md`。其他特殊格式按本片规格增加，不生成无用途文件。

验收记录包含实测输出参数、检查证据、原文要求对照表、已修复问题、尚存限制及未验证项。用简短说明报告结果、重建方法和最重要的不足，不把目标分数或渲染成功当作完成质量的证明。


## 生成前自检

在开始视频制作之前，确认以下条件全部满足：

1. 需求表完整展示并更新；实际未答项已获委托、确认不适用或列为阻断，建议没有冒充用户回答。
2. 所选风格原文已实际读过，必要特征与禁项已具体展开，来源章节可追溯；示例设定与可选项已区分。
3. 主次规则、输出规格、环境和资产边界相容；时间与整数帧数一致，无尚未解决的互斥硬要求。
4. 画面、镜头、配音、音乐、音效和字幕共用时间依据；未经生成的音频时长仍标暂定。
5. 第1—11项均已填好，第10项验收与第11项交付不是等制作结束后才补写。
6. 正文可以独立交给制作AI执行：没有未替换占位符、臆造事实、失效工具命令，也不只让AI参考外部文件自行猜测规范。

有实际阻断先解决；通过后以这份文件作为内部执行依据，继续完成代码、渲染、验收、修复和交付。
